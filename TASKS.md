# UAD 3.6 — task registry

**This file is the single source of truth for what the user has asked for and
what is actually finished.** Every AI agent working in this folder reads it
before starting and updates it when a task changes state. Do not keep a private
to-do list; put it here so the next agent inherits it.

Update it with the tool, not by hand, so the format stays parseable:

```bash
python engine/tasks.py list              # everything, grouped by area
python engine/tasks.py next              # what to pick up now
python engine/tasks.py show T-042        # one task in full
python engine/tasks.py start T-042
python engine/tasks.py done  T-042 "harness 84/84, verified on 12 samples"
python engine/tasks.py block T-042 "needs MyriadPro-Black from the user"
python engine/tasks.py add "Title" --area render --note "asked 2026-09-16"
```

## Rules for agents working here

1. **Read `_work/HANDOFF.md` first** — it carries the current position, what is
   half-finished, and the traps.
2. **Never mark a task `done` without evidence.** Put the evidence in the note:
   a test name, a count, a file. "Looks right" is not evidence.
3. **`partial` is an honest state.** Use it. A task that renders but is not
   verified against the D-1 samples is `partial`, not `done`.
4. **The official specs are the authority**, not screenshots and not another
   vendor's output. Order: Appendix A-1 (delivery/XML), B-1 (display rules),
   C-1 (layout), D-1 (samples), E (style), F-1 (reference), G-1 (cross
   reference), H-1 (compliance rules), and the GSE subschema.
5. **Do not ship a fake control.** Every button must be wired to real state.
6. When the user gives a new instruction, `add` it here in the same turn.

## Status legend

| Status | Means |
|---|---|
| `done` | Implemented **and** verified; evidence in the note |
| `partial` | Implemented but incomplete or unverified |
| `open` | Not started |
| `blocked` | Cannot proceed; the note says what is needed |
