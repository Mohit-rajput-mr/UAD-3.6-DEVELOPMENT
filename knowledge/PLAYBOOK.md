# PLAYBOOK — a UAD 3.6 report in WinTOTAL, from case folder to "ready to sign"

The runbook for the agent, for every report type the kit covers (single-family,
2-4 unit; condo notes in §9). Each step exists because skipping it cost hours
on a real case; the error each step prevents is named (`CATALOG` = `errors/CATALOG.md`).
Worked examples: `cases/worked_example_sf/case.json` (1 unit, 89 Rockland) and
the 3-family `_work/bathbeach/case.json` (1965 20th Dr, delivered 2026-10-02:
FV 0 / schema 0 / UAD 0, ZIP generated by the owner).

**The fastest correct route (proven on both cases):**

    inspection sheet + sketch -> facts (OWNER_NOTES.md)  ->  view every photo
    -> case.json  ->  bridge case --dry-run  ->  bridge case
    -> bridge certify  (until READY)  ->  bridge audit --json case.json  (until clean)
    -> handback  ->  OWNER SAVES IN WINTOTAL

`certify` READY is necessary, not sufficient: `audit` reads the delivered XML
and catches what TOTAL and the UAD rules let through (§6).

---

## 0. Before anything

- `python setup/check.py` passes (Python, packages, specs, TOTAL reachable).
- The signing appraiser is confirmed with the owner; `profiles/<who>.json` and
  its licence + E&O images exist. The case file's `"appraiser"` points at it.
- `python -m bridge.cli detect` (from `total-bridge/`): the ACTIVE report is
  the case's property, a **UAD 3.6 URAR**, 1 building / 1 unit, **not signed**.
  Prefer a **new** report (an import/fill into a report that held another case
  leaves its data behind — CATALOG E-029). The kit's guard refuses a report
  whose subject address does not match the case.
- TOTAL's web-engine build equals the newest folder in `total/builds/`. If
  not, re-extract (check.py prints the commands) and read the diff first.
- **Bridge writes live only in the open session until the OWNER saves in
  WinTOTAL** (CATALOG E-064; `SaveReport` only serializes for the host, and the
  bridge never drives the desktop). Ask the owner to save at the end of every
  working session. On resuming, never assume earlier writes are there:
  `bridge case --dry-run` (or read the key fields) and re-apply what reverted.
- **Someone else may be writing to the same report** (the owner, or another
  agent session). A value that changes without your write -- a DOM, an
  adjustment -- is recorded as "not written by this session" and put to the
  owner; never silently overwritten, never silently trusted.
- **A signed report is read-only** to the bridge (`Report.attach` refuses it);
  `audit` still reads it.

## 1. Read the case folder — as an appraiser would

Typical folder: order/engagement + public record ("Lookup" PDF, ATTOM),
`COMP n MLS.pdf`, `COMP n GEO.pdf`, `exterior/`, room folders, `sketch and
inspection sheet/`.

| Source | Authority for | Notes |
|---|---|---|
| **Inspection sheet** | everything the appraiser observed | **The hard gate — transcribe every line before anything else.** This shop's appraisers **circle or strike what they SELECT**; a stroke is a selection, not an exclusion (read it the other way and half the form inverts). Blank lines (quality, effective age) are *not* answers — handback them. |
| **Measured sketch** | every area | Its level areas are the measured truth. Its "Total Living Area" line is **not** the GLA decision (§2). |
| Photographs | what is visible | Settle conflicts (cooling type, exterior material, grade) — e.g. condensers on a wall = individual/central, not window units. |
| Public record (ATTOM) | parcel, legal, zoning, flood, tax, coordinates, 1004MC | Its bed/bath/GLA are often stale; lower than the sheet/sketch. |
| Engagement letter | client/lender, AMC (+ its state licence), borrower, order no., loan type, product | |
| `COMP n MLS.pdf` | the comparable's sale: status, price, dates, DOM, beds/baths, GLA, year, site, style, basement, garage/parking, cooling, heating | The **structured fields** beat the remarks when they conflict (disclose). **Status matters:** Sold = settled sale; **Pending = accepted contract, no transfer** (§4). Listing photos settle what the text omits (a driveway's surface). |
| `COMP n GEO.pdf` | the comparable's coordinates | Distance and bearing are **computed** (`bridge/locmap.miles_and_bearing`). No GEO sheet → OpenStreetMap Nominatim geocode, recorded as **street-level**, never presented as parcel-precise. |

Write `_work/<case>/facts.py`: every value with its source, and an `OPEN` list
of conflicts and gaps. Researched values (not in the folder) keep their source
and go on the handback.

## 2. The judgement calls that move the value — decide them explicitly

- **GLA vs below grade.** A level that is below grade on *any* side is
  below-grade area, not GLA, whatever its finish. Evidence: windows set high
  on the wall, drop ceilings, grade rising to the rear, the assessor's story
  count and area, what the appraiser named the photo folder. On the worked
  example the sketch said 1,764 "living area"; the owner confirmed **1,000 GLA
  + 764 finished basement** (Level B1, `Below Grade`). Ask when it is not clear.
- **Pending and listed comparables** carry a list price, not a sale price.
- **Comparables across a location boundary** (a parkway, a park, a commercial
  strip) — draw the map (§6) and put it in front of the appraiser; neither rate
  profile has a location rate, so no adjustment is taken without them.
- **The rate profile is chosen by report type** (`casekit.profile`):
  1 unit -> **18 North** ($75/sf GLA, $10/sf site >1,000, $250/yr >5 yr, $10k
  bedroom, $5k half bath, $10k basement / garage / outdoor, 2% listing);
  2-4 units -> **multi-family** (owner 2026-10-02: $150/sf GLA >100 sf, $20/sf
  site >1,000 sf, $250/yr >30 yr, $20k bedroom / full bath, $10k half bath,
  $20k semi-detached vs attached/detached, $20k cooling, $20k per garage,
  $40k full finished basement, $20k deck/patio/porch/balcony/pool, 2% of list
  on a listing). A case may name another with `"adjustment_profile"`. A new
  rate list from the owner becomes a `Profile` in `adjust.py` with tests --
  never typed into grid cells.
- **Every comparable needs days on market** (UAD-1428 is Fatal). A sale known
  only from the deed (no MLS) has none: the owner supplies it from MLS access
  ("never listed" -> 0 with an off-market comment), or the comparable is
  replaced. Prefer comparables WITH an MLS sheet.
- **Reconciliation** (owner 2026-10-02): SHORT. Which sale gets most weight
  and why (recency, proximity, same design, least gross/net adjustment), some /
  support weight for the rest, the value, then the adjustments made listed at
  the bottom. The kit writes it from `reconciliation.summary`; check every
  reason against the numbers before writing it. The final reconciliation
  comment (`REC_MARKET_VALUE`) is prose that states the same value
  (`casekit.final_comment`). **One value everywhere.**

## 3. Photographs — look first (CATALOG E-047)

    python -m bridge.cli sheets --folder "<case folder>" --out "<scratch>"

**View every sheet.** Then a manifest row per picture: section, TOTAL's own
category wording, a description of what it shows. Rules:

- Folder names say where a picture was taken, not what it shows.
- Categories are read from the field's option list; Unit Interior offers
  `Level 1 - Kitchen`, `Level B1 - Family Room` … only once the room table
  holds those rooms — so photos are placed after rooms (the kit's order).
- Categories with no fit (a side elevation, an AC condenser, a meter): leave
  the category empty and describe it — TOTAL accepts a description instead.
- Every picture is placed or listed in `photos_excluded` with a reason (the
  inspection sheet is a source document, not an exhibit).
- **Assignment Information = the appraiser's licence + E&O**, from the profile
  — the kit adds them itself. Never the engagement letter.
- **A photo that looks staged, AI-generated or stock** (perfect lighting,
  slogan posters, mirror reflections that do not match the room, a room larger
  than the sketch) is not placed until the owner confirms it was taken at the
  property. A fabricated exhibit is worse than a labelled missing one.
- A picture the owner pasted directly in TOTAL is not on disk; a full kit
  re-run cannot re-place it. Note it in case.json (`_photo_note`) and fix its
  caption if it still says "no photograph available".
- Missing pictures: `missing_photos` -> a labelled "PHOTOGRAPH NOT AVAILABLE"
  card (E-059). When the owner later sends the picture, replace that row's card
  and caption (read the row index live; pattern
  `_work/bathbeach/place_unit1_bedroom3.py`).
- Comparable photos: the first image of each MLS sheet
  (`pymupdf` → `page.get_images`), one per comparable (`GCn_PHOTO`).
- No location map in the folder → the kit draws one from OpenStreetMap
  (UAD-1283). **View it.**

## 4. The case file

Start from `total-bridge/case_template.json`; compare with the worked
example. Rules that are easy to get wrong:

- **Vocabulary is TOTAL's**, exactly (`Raised Ranch`, `Partially Updated`,
  `10 or more years`, `No Units Above/Below`, `Walk Out`, `Centralized`).
  Copy it from the worked example or read the field's options live
  (`bridge.formkit.field_items`). Never guess.
- **`stored^shown` pick lists store the left half** (CATALOG E-049):
  `No Hazard Zone Noted^None` → write `No Hazard Zone Noted` (writing `None`
  exports a hazard zone *called* None and trips UAD-1374).
- **held_equal**: comparable rows no source states are held equal with the
  subject so they cancel — never invented per comparable. List them on the
  handback.
- **Pending comparable**: `status: "Pending"`, `price: null`, contract date,
  list price. The kit then leaves sale price, transfer terms and sale date
  empty (a pending sale has no transfer — UAD-1439, CATALOG E-048).
- **Driveway**: `vehicle_type: "Driveway"`, `driveway_surface` from the
  listing's photographs (TOTAL requires it — E-048).
- **Subject not listed within a year**: `listed_within_year: false` and the MLS
  as the search source. Never enter a listing status for an unlisted subject —
  it *creates* a listing record (UAD-1204/1208, CATALOG E-050).
- **Weights**: most weight on the comparable needing the least gross
  adjustment; the value must sit inside the range of adjusted (and unadjusted)
  prices. Weights stay in case.json; with `reconciliation.summary` set the
  report text is the short owner form (§2), otherwise the kit writes the
  weighting arithmetic (older single-family form).
- **Exposure time** in days (the kit ticks the checkbox the export needs —
  UAD-1746).
- **Subject wall material** (`subject.exterior_walls`, + `exterior_walls_comment`
  for a mixed facade) from the photographs when the sheet leaves it blank —
  UAD-1080 fires for every dwelling the owner maintains (E-062).
- **Structure design**: `structure_design` on the subject and each comparable
  ("Semi-Detached"); `attachment` alone says only attached/detached. The design
  adjustment and the "row exists" rule both read `design_of()` (E-063).
- **Update scales differ**: kitchen = Fully/Partially/Not; bathrooms =
  Fully/Significantly/Moderately/Not (E-061). Write the right word.

### 2-4 unit case files (proven on 1965 20th Dr)

- Report Setup -> Multi-Family: 1 building, n units, BEFORE the kit runs (E-053).
- `units[]`: per unit levels (above-grade first — E-058), rooms, occupancy,
  quality/condition, `rent` {actual, market, lease_start, month_to_month},
  `other_features` (in-unit washer/dryer — E-059).
- Comparables: `units[]` per comparable (gla, beds, baths_full, below_finished);
  splits nobody publishes are derived from the floor plate and disclosed in
  `_units_source`. GLA/bed/bath/basement adjust on the unit rows; the GLA
  threshold is judged on the building total.
- `rental.comps` (address, unit, lat/lon, rent, beds, baths, gla, floor,
  condition, source + URL in `note`) and `rental.comparison[unit]` (overall,
  adjusted_rent, weight). Areas no listing publishes: NYC PLUTO residential
  area / units (data.cityofnewyork.us 64uk-42ks), disclosed (E-060).
- Rent-grid column headers store the LEFT half of TOTAL's token ("#1") (E-060).
- Lease dates: the owner's, or an estimate tied to a dated fact (e.g. the month
  after the C of O), stated as an estimate in the rental commentary.
- Listing portals (Zillow, Redfin, StreetEasy history, HotPads, Realtor.com,
  Homes.com) answer with human checks or refuse: never bypassed. Apartments.com,
  Corcoran, Compass and StreetEasy building pages often load; OneKey MLS public
  search shows active listings only (sold needs a member login).

## 5. Fill

From `total-bridge/`:

    python -m bridge.cli case --json <case.json> --dry-run   # plan vs the open report
    python -m bridge.cli case --json <case.json>             # fill, then certify

**Re-running part of a case** (photos already placed — a full run re-drops
every photograph): run the kit's own step functions through `rtv.put`, guarded
— pattern `_work/bathbeach/run_reapply.py`: dwelling -> rent schedule ->
rental comps -> grid -> **adjustments + reconciliation LAST** (the grid writes
"$0" into every adjustment row).

The kit's order (do not reorder by hand): guard → parties → AMC block →
subject/site → dwelling → levels + rooms (rows first) → garage/amenity
(category before type) → market → listing → comparable columns → grid →
adjustments (profile by report type, written formatted, nets re-summed — E-038) →
reconciliation → gates (cost/income/revision/supervisor) → photos → map →
certify.

## 6. Certify — the only verdict that counts

    python -m bridge.cli certify --report "<report>"

- Field validation is only true after **every section has rendered** (E-035);
  the kit and certify sweep all sections.
- The form must be left on a **neutral section** (`assignment`), never on
  `order-1`, before anything is exported — the Order section drops the Client
  party from the export (UAD-1542).
- Schema is checked **twice** (a mid-render export once showed a phantom error).
- **TOTAL runs its UAD rules only when field validation is 0** (E-051). "UAD
  Errors: 0" with field validation > 0 means nothing. At FV 0 the worked
  example showed 18 UAD errors that had been invisible.

READY = FV 0, schema 0, UAD rules run and 0.

Then, always:

    python -m bridge.cli audit --json <case.json>

It reads the delivered XML (works on a signed report too) and fails on what
certify let through on 1965 20th Dr (E-065):
- the value differs anywhere (OpinionOfValue, ValueIndicatedBySalesComparison,
  the reconciliation comment) — the owner's rule: ONE value everywhere;
- the reconciliation COMMENT is a bare amount (`REC_MARKET_VALUE` is text);
- an exported adjusted price differs from the kit's — a hidden grid row
  (e.g. ATT_DET_ADJ in a 2-4 grid) holds a value TOTAL's on-screen net omits
  but the export counts;
- the value sits outside the adjusted range;
- a comparable lacks days on market, or carries one the case file does not
  source (someone else wrote it).

DELIVERABLE = certify READY **and** audit clean **and** the owner has saved.

## 7. When an error remains

1. Read the full message and the **exported XML** (`Report.mismo()`) for that
   element — the rule runs over the delivered document, not the screen.
2. Find the mechanism: a missing value? a value in the wrong half of a pick
   pair? a gate (checkbox/count) the exporter needs? a row that should not
   exist? a structural move only TOTAL's own handler can make?
3. Read TOTAL's own code if needed: `total-bridge/tools/dump_bundle.py` keeps a
   copy of the open build's bundle locally (never commit it); search it for the
   field name — validators (`addValidator("X"`), exporters, importers.
4. Fix it **in the MOD** (`bridge/casekit.py`, `formkit.py`, …) with a test,
   add a CATALOG entry, re-run certify. No per-property patches.

## 8. Hand back

`_work/<case>/HANDBACK.md`: the judgement calls (§2), researched values with
sources, conflicts kept with the inspection sheet preferred, rows held equal,
adjustment lines the profile does not rate, anything the owner must check
before signing. Update `_work/HANDOFF.md` and `TASKS.md`.

Add the case's client identifiers (borrower and owner names, phone, e-mail,
loan and order numbers) to `setup/redact_terms.txt`, so
`setup/export_for_device.py` removes them from any note that mentions them
when the folder is sent to another device. Case folders under `_work/` are left
out of an export by default; add a new case folder's path to `CASE_MATERIAL`
in that script.

## 9. Not covered by the case kit yet

**2-4 unit is now covered** (1965 20th Dr, 2026-10-02: units, rent schedule,
rental comparables, per-unit grid rows, multi-family adjustments — §4).
Still not covered: condominium (`CONDO`, project info — see the Shore Parkway
notes in `_work/HANDOFF.md`; that report stopped at FV 9 on missing photos and a
never-listed comparable), co-op, manufactured homes, ADUs,
multiple buildings, a subject **listed** within the year (the kit writes
`SLI_LISTINGS = Yes` plus `listing_fields`, untested live), a subject **prior
transfer** within 3 years (`prior_transfer`, proven on the condo, not through
the kit). Extend the kit the same way: prove each write live, then encode it
with a test.
